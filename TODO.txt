FIDELITY HARNESS  (!) — the thing that makes "Glassbox-level" measurable
[x] Playwright drives fixed demo scenario with recorder active

[x] Produce archive; load in player headlessly; seek to each checkpoint

[x] Fail CI on fidelity regression
[ ] Re-run harness after every rrweb version bump

    RECORDING COST — measured (4s storm churn + media + canvas screens):
      balanced    41 KB   148 events  0 assets  +9.8% wall time
      high       188 KB   148 events  5 assets  +7.1% wall time
      balanced/high archive ratio 0.22x -> the opt-out IS justified
    NOTE: a first attempt measured text-only churn and reported the two presets
    as byte-identical. That was a true measurement of the wrong thing — the
    presets differ on inlineImages/recordCanvas/collectFonts, so the workload
    has to include images, a canvas and a web font or the comparison is vacuous.

    ENDURANCE — the event cap used to LOSE the session. `void stop()` built an
    archive and discarded it, so a tester who ran long got no file and no
    explanation. An involuntary stop now saves itself and records why, in both
    meta.degradations and the widget.

    ASSET EXTERNALIZATION — measured on the fidelity fixture:
      archive 2,012,320 -> 204,128 bytes (9.9x smaller)
      dom-events.json ~2.6MB -> 430KB; 5 deduped assets totalling 149KB
      fidelity UNCHANGED at 99.90% mean, so the shrink is lossless
    Over-budget assets are left INLINE rather than blanked: the budget bounds
    what gets copied into assets/, and silently emptying an image would
    misrepresent the session.

>>> M5 EXIT: a measured fidelity score, not a vibe.
    [x] DONE. 99.90% mean across 10 checkpoints, worst 99.77%, threshold 97%.
          nx run session-demo-app:e2e   (captures live shots + archive)
          nx run session-player:fidelity (replays, pixel-diffs, scores)

    What the harness caught that nothing else did:
      1. The replay iframe rendered 800px BELOW its clipping container, so every
         replay was visually blank. Cause: rrweb's mouse-tail canvas left in
         normal flow because rrweb/dist/style.css was never imported. Every
         earlier test was DOM-based and passed happily.
      2. A whole screen of images silently dropped when SEEKING. rrweb's
         fast-forward is lossy for large mutation batches; playback is not.
      3. The player converted timestamps using the recorder's clock origin, but
         rrweb's replay clock starts at its FIRST EVENT. Every marker and
         jump-to-call was off by that delta.
      4. Session duration came from the DOM stream alone, so network calls that
         finished after the last DOM mutation sat permanently beyond the
         scrubber and could never stop looking "in the future".

    Measurement runs through PLAYBACK, not seeking: seeking scored the same
    session anywhere from 84% to 99.7% depending on machine load, and a metric
    that unstable is worse than none.
